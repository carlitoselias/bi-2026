Seven tool families

Seven families we can combine to suit the project. Each describes a type of tool, not an exclusive use.

FamilyExamplesWhat it adds to the work
AI platformClaude, CodexSupport analysis and production through instructions, context and tools.
BI / visual platformPower BI, Tableau, QuickSight; Flourish, DatawrapperBuild and share dashboards, charts or visual stories, depending on the platform.
LanguagePython, R, JavaScriptExpress processes in code and use libraries for analysis or visualization.
Library / frameworkPlotly, Matplotlib, NetworkX, D3.js, StreamlitAdd chart, network or application features to a language.
Specialized toolGephi, Cytoscape, QGISWork on specific tasks, such as networks or geographic information.
Office toolsExcel, Google Sheets, PowerPointWork with tables and charts in spreadsheets; organize and present results in slides.
DesignIllustrator, InkscapeCompose, illustrate and refine the graphic presentation.
One possible combination

Claude or Codex support work with Python and Plotly; Illustrator can help prepare a final piece. The team checks the data and decisions.

The family does not determine effort, cost or quality. Review each tool and how it will be used. The seven families can combine to produce a report, a presentation or a web page. Next, we will look at choices within each family.

05
Visualization tools

AI: from chat to work on a project

Claude Code and Codex offer broadly similar capabilities. For the tasks in this class, we can use either one.

ChatGPT / Claude · chat

For exploring a question, analyzing files and creating charts, documents or prototypes through a conversation.

Strengths Start with the data and context you share, without preparing a code project.

Considerations It works with the files and connections available in that session. Moving the result into a project and maintaining it may require extra steps.

Claude Code / Codex · agents

For working on a project: reading and editing files, running code, checking results and continuing iterations.

Strengths Both can build charts, dashboards, web pages and other materials. With the right tools and permissions, they can also interact with the computer.

Considerations Access and features depend on the environment. Both need context, rules and checks of the output.

Choose for the working environment. We do not reserve a visualization type for a particular brand. File and tool access, continuity and review matter. An agent can also run on the web: the distinction is more than “browser or desktop”.

06
Visualization tools

Dashboards: start with the context

Data sources, audience access and updates matter as much as the chart.

Power BI

If the team already works with Microsoft and needs shared reports.

Strengths Connects sources, models data and combines views with filters.

Considerations Agree on measures, permissions and licenses for publishers and readers.

Tableau

If you need storytelling tools to guide the audience through findings.

Strengths Its Stories feature arranges views and dashboards in a sequence, with text explaining each step.

Considerations Define where it will be published. Tableau Public means public exposure.

QuickSight

If the project already uses AWS and needs dashboards in that environment.

Strengths Integrates BI with AWS services and distribution options.

Considerations Review configuration, access and costs for the intended use.

Other paths: Data Studio for connected reports, for example from Sheets or BigQuery; Datawrapper for charts, maps and tables; Flourish for visuals and stories based on templates. Choose for the product you need.

07
Visualization tools

Languages: choose what you can maintain

Python and R support data analysis and visualization. On the web, JavaScript works alongside HTML and CSS.

Python

If you need cleaning, analysis and chart generation in one process.

Strengths Its ecosystem helps repeat tasks and connect different steps.

Considerations Its flexibility requires choosing libraries and adjusting charts in code; a simple piece may need more preparation.

R

If the work centers on statistical analysis and charts linked to that analysis.

Strengths Integrates statistical methods and packages such as ggplot2.

Considerations To turn the analysis into an interactive app, you need tools such as Shiny and an environment to host it.

JavaScript + HTML / CSS

If you need a visualization inside a web page, with control over its appearance and responses.

Strengths HTML organizes content, CSS defines presentation and JavaScript connects actions to what the page displays.

Considerations Adds interface work: states, accessibility and different screen sizes.

Three complementary functions on the web: HTML is a markup language, CSS is a style language and JavaScript is a programming language.

08
Visualization tools

Libraries: start with the output

A figure, an interactive chart and an application have different needs. These are not difficulty levels.

A figure

Matplotlib if you need to adjust axes, annotations and composition in Python.

Strengths Fine control and export for documents.

Considerations Adjustments are coded. It also supports interaction; it is not limited to images.

An interactive chart

Plotly if you need selection, zoom and a shareable HTML output.

Strengths Built-in interactions and several chart types.

Considerations Exporting HTML does not add a server or updated data on its own.

An application

Streamlit or Dash if you need to connect controls, calculations and multiple views.

Strengths They structure the application around the analysis.

Considerations Needs execution, deployment and maintenance. Check all states.

More options: Seaborn for statistical charts; Altair for declarative specifications; D3.js for custom web composition; NetworkX for network analysis. They can be combined.

Matplotlib ↗ · Plotly: HTML ↗ · Streamlit ↗ · Dash ↗ · NetworkX ↗ · D3 ↗

Visualization tools

Specialized tools: follow the data structure

Relationships between entities and geographic locations raise different questions.

Gephi / Cytoscape

Choose for working with nodes and links. Gephi explores layouts and metrics; Cytoscape is another option, with an ecosystem linked to biological networks.

Strengths Operations focused on networks.

Considerations Define what each link represents. Proximity in a layout does not prove a causal relationship.

QGIS

Choose for combining geographic layers and studying location, coverage or distance.

Strengths Tools for spatial analysis and map composition.

Considerations Check coordinates, projection and units before measuring or comparing.

An alternative with code: NetworkX for networks; GeoPandas for geographic data. Choose them if you need repeatable operations that the team can maintain.

Visualization tools

Office tools: calculation and presentation work together

The spreadsheet organizes data. The presentation organizes the explanation for an audience.

Excel

If the team maintains workbooks and needs to review tables, formulas and charts.

Strengths Data and calculations remain visible in one file.

Considerations Avoid undocumented manual steps; check ranges and formulas when adding rows.

Google Sheets

If several people need to review and edit a shared table in the browser.

Strengths Makes it easier to work on one common version.

Considerations Agree on permissions, structure and ownership; check limits and formulas.

PowerPoint

If you need a sequence of slides to explain findings.

Strengths Combines charts, text, annotations and presenter notes.

Considerations A pasted image does not update. Linked charts depend on the source file.

Before delivery: change a test value in the source and check what updates. A screenshot, an embedded object and a link behave differently.

Design: refine the piece without changing the data

Use it for composition, typography and illustrations when chart editing is not enough.

Illustrator

If the team uses Adobe and you need to edit a vector graphic.

Strengths Provides detailed control over shapes, text and composition.

Considerations Review licensing, formats and how you will retain the link to the data.

Inkscape

If you want a free, open-source vector editor for SVG.

Strengths Edits shapes, text and illustrations in a web format.

Considerations Check fonts and compatibility when exchanging files with other applications.

Keep the original and record adjustments. An editable export does not guarantee updates from new data. When editing, preserve lengths, areas, positions and scales that encode values.

The web: where these tools meet

A web page can combine text, charts and controls. Choose how to build it based on what it must do.

Tell a story

HTML + CSS for structure and design; JavaScript if you need behavior. You can also use a website builder.

Strengths Control over reading order.

Considerations Prepare for mobile, accessibility and content updates.

Embed a visualization

Datawrapper, Flourish or BI to embed a piece published on another platform.

Strengths Reuses an existing visualization.

Considerations Depends on the service and its permissions. Publishing on the web is not the same as private sharing.

Create an application

Streamlit, Dash or web development if controls must run calculations and coordinate views.

Strengths Lets users explore new questions.

Considerations Define hosting, execution, access and maintenance.

The web is a delivery medium; tool families are ways to build. Claude or Codex can help build it. The team remains responsible for the published data and how it works.

Working with agents

What you give the agent and how it can act

The task guides the work. Context, tools and permissions define how it can be done.

Goal

What must it achieve, and for whom?

Compare completion rates at sites A and B for the coordination team.

Context

What does it need to interpret the task?

One row per site. Completion rate = completed / assigned. Use the project’s visual rules.

Input data

Which files or sources will it use?

Use data.csv and its column dictionary. If a definition is missing, ask before calculating.

Output format

What must it deliver, and how will it be used?

Deliver an HTML page with a chart, table, total and site filter; it must be readable on mobile.

Constraints

Which limits must it respect?

Keep the original data. Do not publish. Keep each site’s color and label.

Checks

What evidence makes the work acceptable?

Check calculations against the table. Test the filter and confirm that the chart, table and total agree.

Include only what the task needs. If you have an example of an acceptable output, attach it as a reference.

Harness: the environment that enables action

Coordinates the cycle between the model, its tools and results. The prompt is one part of that environment.

Context

Instructions, files and session state.

Tools

Actions and results returned to the model.

Permissions

Configured access and approvals.

Continuity

Work records and context management.

The same model can act differently depending on the available context, tools and limits.

If you want to…Prepare the environmentCheck
Review dataProvide the table and its dictionary; allow reading and calculation. Save results in a separate folder.That it can open the files and preserve the original.
Build a visualizationOpen the project, allow editing and execution, and provide a preview or browser.That it checks calculations, filters and presentation as well as code.
Resume another sessionIdentify the current README, backlog and handoff; ask it to review the current state before continuing.That it distinguishes completed from pending work and does not repeat tasks.

In Codex or Claude Code, you already use a harness. Configure the environment provided by the application; you do not need to program one. Writing “do not publish” guides the agent; restricting permissions controls access.

Markdown: text with structure

Plain text with marks that make sections, lists and hierarchy explicit.

What we write

# Project

## Goal
Compare completion rates by site.

## Constraints
- Keep the original data.
- Keep each site’s colors.

## Checks
- Check calculations against the table.

What it adds to unstructured text

# identifies a title; ##, a section; -, a list item. These marks separate blocks and express their relationships.

This makes instructions easier to find, review and reuse. It also helps the model distinguish sections of the task.

A .txt file can contain the same marks. The benefit comes from structure, not changing the extension; it does not guarantee fewer tokens either.

Also used in training

Markdown represents content and structure as text. For example, Nougat was trained to convert document pages into Markdown. This does not mean all models use the same training data or formats.

Common Markdown files in a project

Separate responsibilities to reduce contradictions.

DocumentQuestion it answers
README.mdWhat is the project, and how is it used?
AGENTS.md / CLAUDE.mdWhich rules must the agent follow here?
BACKLOG.mdWhat work remains, and what is its status?
handoff.mdWhere did the last session stop?
DESIGN.md or design.mdWhich design decisions must we keep?
DATA.md or a README sectionWhat does a row represent, how is the rate calculated, and how are missing values treated?
DECISIONS.md / SOURCES.mdWhat was agreed, and what supports it?
DONE.md or a README sectionWhich common conditions must the work meet to be considered complete?

Names and conventions

Instruction files have loading mechanisms specific to each application. Other names are project conventions: link or identify them so they are consulted. Not every project needs a file for each responsibility. Create one when it meets a specific need.

18
Working with agents

README: the project’s entry point

Explains what we are building and how to open, use and review the result.

Example · README.md

# Site comparison
## Purpose
Compare completed and assigned activities.
## How to open
Open view.html in the browser.
## How to review
Test the site filter and check the table.
## Documents
- DATA.md: definitions and calculations.
- DESIGN.md: visual rules.
- BACKLOG.md: pending work.

Good practices

Start with use

Explain the purpose, audience and entry point. State any installation or setup steps.

Test the instructions

Another person must be able to follow them. Update paths and commands when the project changes.

Link without duplicating

Point to the document that owns each definition or rule; avoid copying its content.

The README is a map of the project. Pending work belongs in the backlog; session state belongs in the handoff.

Working with agents

Instructions: rules for working here

AGENTS.md or CLAUDE.md preserves agreements that should guide more than one task.

Example · AGENTS.md / CLAUDE.md

# Project rules
## Before making changes
- Read DATA.md and DESIGN.md.
## During the work
- Keep the original data.
- Keep each site’s color and label.
## Before declaring completion
- Check calculations against the table.
- Review the mobile view.
- Record what was checked.
- Do not publish without authorization.

Good practices

Write verifiable rules

“Check calculations against the table” specifies an observable action. “Do it well” defines no criterion.

Keep rules current

Include stable agreements, remove contradictions and link to details. Today’s tasks belong in the request or backlog.

Check what gets loaded

Codex uses AGENTS.md; Claude Code uses CLAUDE.md and supports AGENTS.md depending on version and configuration. Check the mechanism in your environment.

A written rule does not grant or block system permissions. Access is configured in the environment.

Working with agents

Backlog: work and completion criteria

Keeps pending work, its status and the evidence needed to close it.

Example · BACKLOG.md

## P-03 · Review the mobile view
Status: in review
Owner: visualization team
Scope: chart, table and site filter.
Completion criteria:
- Readable labels without clipping.
- Filter, chart and total agree.
- Keyboard use checked.
Evidence: screenshots and test results.
Pending: keyboard review.
Dependency: agree on labels in DESIGN.md.

Good practices

Specific tasks

Separate work that can be reviewed independently. Assign a stable ID and an owner.

Define completion

Describe an observable result. “Implemented” can still mean “in review”.

Update with evidence

Record what was checked, what remains and what blocks the work. Do not close a task just because the agent says “done”.

A pending task does not authorize execution. Agree on the task to work on now and keep the rest in their actual states.

Working with agents

Handoff: resume the work

Summarizes the last session and points to files that hold the current state.

Example · handoff.md

# Session close · Nov 7
Done: completion-rate view implemented.
Checked: filter A and total against the table.
Not checked: keyboard use.
Pending: P-03 in BACKLOG.md.
Files: view.html, DATA.md, DESIGN.md.
Recent decision: D-01 in DECISIONS.md.
Next step: complete the review of P-03.
Publishing: not authorized.

Good practices

Separate done from checked

State what exists, what was verified and what remains uncertain.

Point to the current state

Use backlog IDs and file paths. Do not copy the whole conversation or create another task list.

Use it when resuming

Ask the agent to read it and compare it with current files. A summary can become outdated.

Update the note when closing a session. If you keep a history, distinguish the current version from earlier ones.

Design: preserve decisions

Defines the rules that make pieces read as parts of the same system.

Example · DESIGN.md

# Visual system
## Identity
- Site A: blue + label A.
- Site B: orange + label B.
## Comparison
- Rates between 0 and 100 % in these views.
- A title that communicates the finding.
## Interaction
- The filter updates chart, table and total.
## Review
- Test contrast and mobile reading.
- Compare with the accepted screenshot.

Good practices

Define uses, not just colors

Record what each element means and when to use it: typography, spacing, scales, annotations and states.

Keep accepted examples

Include a visual reference and explain which decisions must remain. A screenshot alone does not describe every interaction.

Review the actual result

Check the piece with real text and data. A size rule does not guarantee the content will fit.

These rules belong to the project. Not all charts need the same scale or every visual element at once.

DATA: agree on what the data mean

Prevents two people from calculating different figures because they interpret columns differently.

Example · DATA.md

# Data definitions
Unit: one row per site in the period analyzed.
Key: site.
Assigned: planned activities (count).
Completed: finished activities (count).
Rate: completed / assigned × 100.
Total: sum counts before dividing.
Zero denominator: rate unavailable.
Missing values: do not replace with zero.
Source and cutoff: record source and date.

Good practices

Define each field

State type, unit, allowed values and what one row represents. Document keys and relationships.

State the calculations

Write formulas, denominators and rules for missing values, filters, joins and derived variables.

Verify with a few cases

Check calculations by hand and keep the data version used. If a definition changes, review its effects.

This can be a README section or a separate file. Describe how to access data without copying private information into the document.

Decisions and sources: keep the reasons

Keep the agreement, its rationale and the evidence needed to review it later.

Example · DECISIONS.md / SOURCES.md

## D-01 · Calculate the combined rate
Decision: sum completed and assigned activities
before dividing; do not average site rates.
Reason: each activity must have equal weight.
Alternative: give each site equal weight.
Evidence: DATA.md and a check calculation.
Status: agreed by the team · Nov 7.
Review if the unit of analysis changes.

## S-01 · Data source
Record origin, date, version and limitations.

Good practices

Distinguish proposals from agreements

Record date, owner and status. An agent’s suggestion is not a team decision.

Keep the rationale

Explain why an option was chosen and which alternative was rejected. Link to the current rule where relevant.

Make evidence traceable

For each source, give a link or location, version or date, and the claim it supports. Separate facts from interpretations.

They can share a short document. Separate them as they grow; keep a clear reference between each decision and its source.

Definition of Done: when work is complete

An agreement on the quality conditions the work must meet.

Example · DONE.md

# Definition of Done

- [ ] Calculations checked against the table.
- [ ] Sources, units and period visible.
- [ ] Filters and controls checked.
- [ ] Reading reviewed on desktop and phone.
- [ ] Documentation updated.
- [ ] Review evidence saved.

## Evidence
Check table and screenshots in /review.
Record who reviewed which version.

Good practices

Agree before building

Define quality conditions for the team’s work. Use them in every review.

Separate common and specific criteria

The DoD requires checking filters. A specific task’s criterion states, for example, what the site filter must show.

Support each check

Verify calculations with another method and review the final view. Save results: ticking a box does not prove a test passed.

It can live in the README or a linked file. DONE.md is a project convention. If a condition is unmet, record the pending work before declaring completion.

Plugin, skill, tool and MCP

Four concepts with different roles that can work together.

ConceptWhat it isWhen to use itExample
PluginAn installable package that can combine skills and connections.When you need to add or share several related capabilities.A reporting package with a review skill and data access.
SkillInstructions and resources for a repeatable procedure.When you want the same steps and criteria for recurring tasks.Review a dashboard: check calculations, test filters and check readability.
ToolA function the agent can execute to perform an action.When it needs to act on files, calculations or services.Query a table to verify the total shown in a dashboard.
MCPA protocol connecting AI applications with tools and resources.When you need access to a service through a compatible MCP server.Connect a database to inspect its schema and run authorized queries.

They can combine: a plugin includes a skill; the skill guides tool use; some tools connect through MCP. Connections and permissions determine which actions are available.

Process: grow without accumulating files

Structure should help the work, without becoming another task to maintain.

At the start

A clear goal, sources, working folder and review criteria.

When work repeats

Stable rules and reusable procedures.

When work continues

Pending tasks, decisions, versions and a brief handoff between sessions.

Signs that you should simplify

If several files repeat the same decision, choose one main source. If an instruction no longer applies, update it. If the agent must read a huge history for a small correction, improve links and the entry context.
